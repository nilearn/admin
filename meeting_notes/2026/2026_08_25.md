## PRs

### 6411 - use numpy / scipy as transitive dependencies

https://github.com/nilearn/nilearn/pull/6411

Medium impact / Medium priority.

It was mentioned in a comment (https://github.com/nilearn/nilearn/issues/6374#issuecomment-4914770811)
that our policy regarding which version of numpy / scipy we support is a bit a unclear:
unofficiallly we tend to lag a bit behind the SPEC0 recommendation to allow more flexibility to our users.

This PR (initially mostly a feasibility test) aims at actually removing numpy and scipy
as explicit depenencies in the repo as we can just rely the fact
that some other of our direct dependencies (sklearn, nibabel, pandas...)
do declare which versions of numpy and scipy they need.
The idea would be to add, when needed, which version of numpy or scipy we do NOT support
if they caused some bugs on our side (currently not the case).

Note: the PR is gigantic because there is a uv.lock in it - whether we want to add it to the repo should be a separate issue / PR.

Note this would only be merged for version 0.15.0

Remi: I am usually in favor of only declaring our direct dependencies
but would be curious to know how others feel.

### 6437 - Compare gallery doc images between stable and dev builds

https://github.com/nilearn/nilearn/pull/6437

Medium impact / Medium priority.

This PR adds a script to compare the images of our full doc build on main (dev)
to the last stable version.
The goal is to mostly help catch "regressions"
and ensure better reproducibility across versions:
this mechanism would have been useful when I recently removed (by mistake)
the data standardization of several of our examples leading to some massive drops in performance.

Remi: want to know how others feel about such "stability" check that could avoid some footgun experiences...
